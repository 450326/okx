# 数据库表结构设计

## 1. 文档目标

本文档用于定义`真实与模拟期货交易平台`一期数据库结构，目标是支持以下核心能力：

- 用户与登录
- 模拟盘与真实盘模式隔离
- 账户资产管理
- 持仓管理
- 订单管理
- 成交管理
- 资金流水
- 交易所 API 绑定
- 行情品种配置

一期数据库建议使用：

- `PostgreSQL` 作为主数据库
- `Redis` 作为实时缓存和行情缓存

## 2. 设计原则

- 所有真实 / 模拟数据必须通过 `mode` 字段隔离
- 所有金额字段使用 `numeric`，禁止使用 `float`
- 所有主键统一使用字符串 ID 或雪花 ID
- 核心业务表必须保留 `created_at` 与 `updated_at`
- 强平、手续费、盈亏必须能追溯到订单或持仓
- 行情实时流不全部落库，数据库仅保存配置和必要快照

## 4. 核心表总览

一期建议至少包含以下表：

- `users` 用户表
- `user_sessions` 用户会话表
- `exchange_accounts` 交易所 API 绑定表
- `symbols` 交易品种表
- `symbol_risk_configs` 品种风险配置表
- `account_balances` 账户资产表
- `positions` 持仓表
- `orders` 订单表
- `order_fills` 成交表
- `ledger_entries` 资金流水表
- `liquidation_records` 强平记录表
- `user_favorites` 自选品种表

## 5. 详细表设计

## 5.1 users

### 用途

保存用户基础信息。

### 建表建议

```sql
create table users (
  id varchar(32) primary key,
  email varchar(120) not null unique,
  password_hash varchar(255) not null,
  nickname varchar(60) not null,
  status varchar(20) not null default 'active',
  default_mode varchar(20) not null default 'simulation',
  last_login_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| id | varchar(32) | 用户 ID |
| email | varchar(120) | 邮箱 |
| password_hash | varchar(255) | 密码哈希 |
| nickname | varchar(60) | 昵称 |
| status | varchar(20) | 用户状态 |
| default_mode | varchar(20) | 默认模式 |

## 5.2 user_sessions

### 用途

保存登录会话和 refresh token 信息。

```sql
create table user_sessions (
  id varchar(32) primary key,
  user_id varchar(32) not null references users(id),
  refresh_token_hash varchar(255) not null,
  user_agent varchar(255),
  ip varchar(64),
  expires_at timestamptz not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

### 索引建议

```sql
create index idx_user_sessions_user_id on user_sessions(user_id);
```

## 5.3 exchange_accounts

### 用途

保存用户绑定的真实交易所 API 账户信息。

### 注意

- `api_secret` 必须加密保存
- 可额外接入 KMS 或服务端加密

```sql
create table exchange_accounts (
  id varchar(32) primary key,
  user_id varchar(32) not null references users(id),
  exchange varchar(20) not null,
  label varchar(60) not null,
  api_key_encrypted text not null,
  api_secret_encrypted text not null,
  passphrase_encrypted text,
  is_testnet boolean not null default false,
  status varchar(20) not null default 'active',
  last_test_at timestamptz,
  last_sync_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

### 索引建议

```sql
create index idx_exchange_accounts_user_id on exchange_accounts(user_id);
```

## 5.4 symbols

### 用途

保存平台支持的可交易合约配置。

```sql
create table symbols (
  id varchar(32) primary key,
  symbol varchar(50) not null unique,
  base_coin varchar(20) not null,
  quote_coin varchar(20) not null,
  contract_type varchar(30) not null default 'perpetual',
  status varchar(20) not null default 'active',
  price_precision int not null,
  qty_precision int not null,
  min_qty numeric(30, 12) not null,
  min_notional numeric(30, 12) not null,
  max_leverage int not null,
  sort_order int not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## 5.5 symbol_risk_configs

### 用途

保存品种风控参数和费率参数。

```sql
create table symbol_risk_configs (
  id varchar(32) primary key,
  symbol varchar(50) not null references symbols(symbol),
  maintenance_margin_rate numeric(10, 6) not null,
  maker_fee_rate numeric(10, 6) not null,
  taker_fee_rate numeric(10, 6) not null,
  default_slippage_rate numeric(10, 6) not null default 0,
  max_position_notional numeric(30, 12),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique(symbol)
);
```

## 5.6 account_balances

### 用途

保存用户在不同模式下的账户资产汇总。

### 说明

一位用户会有两套账户资产：

- 一套 `simulation`
- 一套 `live`

```sql
create table account_balances (
  id varchar(32) primary key,
  user_id varchar(32) not null references users(id),
  mode varchar(20) not null,
  currency varchar(20) not null default 'USDT',
  wallet_balance numeric(30, 12) not null default 0,
  available_balance numeric(30, 12) not null default 0,
  position_margin numeric(30, 12) not null default 0,
  order_margin numeric(30, 12) not null default 0,
  unrealized_pnl numeric(30, 12) not null default 0,
  realized_pnl numeric(30, 12) not null default 0,
  equity numeric(30, 12) not null default 0,
  version int not null default 0,
  updated_at timestamptz not null default now(),
  created_at timestamptz not null default now(),
  unique(user_id, mode, currency)
);
```

### 说明

- `version` 用于乐观锁，避免并发下单导致资金写错

## 5.7 positions

### 用途

保存当前持仓和历史持仓。

```sql
create table positions (
  id varchar(32) primary key,
  user_id varchar(32) not null references users(id),
  mode varchar(20) not null,
  venue varchar(20) not null,
  symbol varchar(50) not null references symbols(symbol),
  side varchar(20) not null,
  margin_mode varchar(20) not null default 'isolated',
  leverage int not null,
  qty numeric(30, 12) not null,
  entry_price numeric(30, 12) not null,
  mark_price numeric(30, 12) not null default 0,
  last_price numeric(30, 12) not null default 0,
  notional numeric(30, 12) not null,
  initial_margin numeric(30, 12) not null,
  maintenance_margin numeric(30, 12) not null,
  liquidation_price numeric(30, 12),
  isolated_margin numeric(30, 12) not null,
  unrealized_pnl numeric(30, 12) not null default 0,
  realized_pnl numeric(30, 12) not null default 0,
  take_profit_price numeric(30, 12),
  stop_loss_price numeric(30, 12),
  status varchar(20) not null default 'open',
  opened_at timestamptz not null default now(),
  closed_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

### 索引建议

```sql
create index idx_positions_user_mode_status on positions(user_id, mode, status);
create index idx_positions_symbol on positions(symbol);
```

### 设计说明

- 一期采用单向持仓，因此可以允许同一用户同一品种同方向聚合为一条持仓
- 如果你后面要改成双向持仓，需要调整唯一性策略

## 5.8 orders

### 用途

保存所有委托订单。

```sql
create table orders (
  id varchar(32) primary key,
  user_id varchar(32) not null references users(id),
  mode varchar(20) not null,
  venue varchar(20) not null,
  exchange_account_id varchar(32) references exchange_accounts(id),
  symbol varchar(50) not null references symbols(symbol),
  side varchar(20) not null,
  action varchar(20) not null,
  order_type varchar(20) not null,
  margin_mode varchar(20) not null default 'isolated',
  leverage int not null,
  reduce_only boolean not null default false,
  qty numeric(30, 12) not null,
  price numeric(30, 12),
  trigger_price numeric(30, 12),
  avg_fill_price numeric(30, 12),
  filled_qty numeric(30, 12) not null default 0,
  notional numeric(30, 12) not null default 0,
  fee_rate numeric(10, 6) not null default 0,
  fee numeric(30, 12) not null default 0,
  source varchar(20) not null default 'user',
  status varchar(30) not null,
  reject_reason varchar(255),
  exchange_order_id varchar(100),
  client_order_id varchar(100),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  cancelled_at timestamptz
);
```

### 索引建议

```sql
create index idx_orders_user_mode_created_at on orders(user_id, mode, created_at desc);
create index idx_orders_status on orders(status);
create index idx_orders_exchange_order_id on orders(exchange_order_id);
```

## 8. Redis 设计建议

实时交易系统不建议把所有行情都直接落数据库，应配合 Redis：

## 8.1 Redis Key 建议

```txt
ticker:BTC-USDT-SWAP

mark_price:BTC-USDT-SWAP
user_assets:simulation:u_1001
user_assets:live:u_1001

```

## 8.2 Redis 用途

- 缓存最新行情
- 缓存标记价格
- 缓存用户实时资产摘要
- 缓存持仓快照
- 做 WebSocket 推送加速

## 9. 一期关键 SQL 约束建议

## 9.1 资金字段非负约束

可以为部分字段增加 check：

```sql
alter table account_balances
add constraint chk_account_balances_nonnegative
check (
  wallet_balance >= 0
  and available_balance >= 0
  and position_margin >= 0
  and order_margin >= 0
);
```

## 9.2 杠杆约束

```sql
alter table positions
add constraint chk_positions_leverage
check (leverage >= 1 and leverage <= 125);
```

注意：

- 数据库可以放宽到 125
- 实际业务层仍建议一期只开放到 50

## 10. 典型业务落库流程

## 10.1 模拟开仓流程

涉及表：

- `orders`
- `order_fills`
- `positions`
- `account_balances`
- `ledger_entries`

执行顺序建议：

1. 创建订单记录
2. 风控校验
3. 生成模拟成交
4. 更新持仓
5. 扣减手续费并写流水
6. 更新账户余额

## 10.2 平仓流程

涉及表：

- `orders`
- `order_fills`
- `positions`
- `ledger_entries`
- `account_balances`

执行顺序建议：

1. 创建平仓单
2. 成交
3. 计算已实现盈亏
4. 更新持仓数量或关闭持仓
5. 写入手续费流水
6. 写入已实现盈亏流水
7. 更新账户余额

## 10.3 强平流程

涉及表：

- `positions`
- `liquidation_records`
- `ledger_entries`
- `account_balances`

执行顺序建议：

1. 计算仓位权益是否低于维持保证金
2. 写入强平记录
3. 修改持仓状态为 `liquidated`
4. 写入强平流水
5. 更新账户余额

## 11. Prisma 模型建议

如果你使用 Prisma，可以先按下面思路建模：

```prisma
model User {
  id            String   @id
  email         String   @unique
  passwordHash  String   @map("password_hash")
  nickname      String
  status        String
  defaultMode   String   @map("default_mode")
  createdAt     DateTime @default(now()) @map("created_at")
  updatedAt     DateTime @updatedAt @map("updated_at")

  balances      AccountBalance[]
  positions     Position[]
  orders        Order[]
}

model AccountBalance {
  id               String   @id
  userId           String   @map("user_id")
  mode             String
  currency         String
  walletBalance    Decimal  @map("wallet_balance")
  availableBalance Decimal  @map("available_balance")
  positionMargin   Decimal  @map("position_margin")
  orderMargin      Decimal  @map("order_margin")
  unrealizedPnl    Decimal  @map("unrealized_pnl")
  realizedPnl      Decimal  @map("realized_pnl")
  equity           Decimal
  version          Int
  createdAt        DateTime @default(now()) @map("created_at")
  updatedAt        DateTime @updatedAt @map("updated_at")

  user User @relation(fields: [userId], references: [id])

  @@unique([userId, mode, currency])
  @@map("account_balances")
}
```

## 13. 最终建议

数据库一期最关键的是这三点：

- 真实盘与模拟盘必须隔离
- 资金流水必须完整可追溯
- 金额字段必须全部使用高精度数值类型

推荐你的实际顺序：

1. 先建核心 8 表
2. 跑通模拟盘闭环
3. 再加强平记录、自选、风险日志
4. 最后接真实交易同步日志
